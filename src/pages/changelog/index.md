## [0.31.0] — 2026-10-23

The router keeps an agent loop on one model, ends a native dispatch with the
request that started it, and reads its deciders more strictly. Routing
decisions change (the excerpt, out-of-schema answers), so the release is a
minor one.

### Added

- **`X-Router-Conversation` keeps a conversation on its first route.** An
  agent loop sends one request per step, and every step was decided on its
  own: a step with tools needs the mid band, and past 20,000 estimated
  tokens `long` asks for the frontier, so the model changed halfway through
  the task and the provider's prompt cache went with it. With the header,
  the first `auto` request is decided and pins the conversation to the
  profile it dispatched; every later one goes there without a decider call,
  as if the client had named it (mode `pinned`, `X-Router-Pin: held`,
  `router.pin`). A request the pinned profile cannot take is refused with
  `pinned` naming it, never sent elsewhere. Pins live in memory only (1,024
  conversations, 12 hours idle); the id is never echoed or written to
  receipts. Without the header nothing changes. A malformed id is
  `400 invalid-conversation`.
- **`eval --output` writes `decisions.jsonl`**: one line per prompt and
  paraphrase with the profile chosen, the signals, the reasons and the
  decider's own answer, never the prompt. The report gave only aggregates,
  so a decision that fell to the default could not be traced to the signal
  that sent it there.

### Changed

- **The excerpt drops the blocks coding harnesses add to a user turn**
  before trimming it to 2,048 characters, and the arithmetic check ignores
  them: a date in a session block no longer kept a Jev decision at the mid
  band. The list was checked against each harness's source:
  `<system-reminder>` (OpenCode; Claude Code through translators such as
  claude-code-router), `<environment_context>` (Codex), `<environment_details>`
  (Roo Code). A user turn that is only such blocks is passed over for the
  one before it. `input: full` still sends everything as it is.

- **The GLM runner sets no spending cap unless asked.** It passed Claude
  Code `--max-budget-usd 2.00` on every run, but Claude Code counts that
  amount at its Opus list (GLM runs under the `opus` alias), many times
  GLM's price, so a GLM run stopped far below $2 of GLM. `--max-cost-usd`
  still sets one, validated as a positive amount, and its help says the
  amount is Claude Code's count, not GLM dollars.

### Fixed

- **An out-of-schema answer from a decision service is undecidable**, as
  the router page said. A probability or confidence that is not a finite
  number in [0, 1], a difficulty outside its scale, or a distribution that
  does not sum to 1 was read as it came (`NaN` included, which Python's JSON
  parser accepts); it now voids the answer, with a warning naming the value.
  A classifier's difficulty or `p_needs_strong` outside 0..1 is no longer
  clamped into range: it is undecidable too.

- **A native dispatch outlived the request.** A client that gave up, or a
  `serve` that stopped, left the dispatcher running: a GLM run went on for
  more than 30 minutes after both were gone, and the runner ignored SIGTERM
  while its Claude Code child worked. The dispatcher now runs in its own
  process group; when the client hangs up or `serve` stops, the group gets
  SIGTERM and, 10 s later, SIGKILL.
- **GLM through Claude Code (`claude-zai`) was priced at Opus rates.** The
  runner reported Claude Code's own cost as the provider's, but Claude Code
  runs GLM under the `opus` alias and prices it at its Opus list: a one-line
  question was disclosed at $0.022 where GLM's price comes to $0.0006. The
  runner reports no provider cost now, and the router prices GLM's token
  counts at the profile's rate.

### Documentation

- The router page recommends pinning the Jev version an `eval` measured
  instead of `jev-latest` (Jev answered as 1.13.0 on 2026-10-15 and as
  1.14.0 a week later), and says what Jev's confidence measures. Sage's band
  mass was tried in its place and kept out: replayed on 20 recorded answers
  it changed no answer and sent two more requests to the default.

## [0.29.0] — 2026-10-19

A model you cannot reach is set aside before the decision, not chosen and
failed.

### Changed

- **Unreachable pool profiles are set aside.** Before the decision, every
  pool profile is checked without a model call: an HTTP profile needs its
  key (the named variable or the kit's key file), a native runner's `check
  --json` must select a backend, `codex` and `claude` must be on PATH, and a
  profile that names `credential_env` needs that variable, as
  `delegation-run` does. A profile that fails is left out like a context too
  small and listed under `blocked` as `unreachable: <why>`, so the cheapest
  profile you can actually use answers. Before, the policy could pick a
  model whose key or login was missing and the request failed, with no
  fallback. `serve` checks once when it starts and names what it set aside
  in its start line; `decide` checks every time (the native runners' checks
  run in parallel, about 3 s at worst); a login that lapses later still
  fails at dispatch, with its own error. A profile named as `model` is
  never set aside: it fails as before.
- **`check` and `doctor` say what this machine can reach.** Each pool entry
  carries `reachable`, and an unreachable profile, or an unreachable `llm`
  decider, is a warning. `decide --lane` says "no reachable pool profile
  takes the role" when the only candidates are unreachable, and names the
  reason when the decision lands on an unreachable default.

## [0.28.0] — 2026-10-19

The rating becomes a minimum score; the cheapest model that reaches it
answers.

### Changed

- **Policy `floor-v1` replaces `tiered-v1`.** The decider's rating becomes a
  minimum score on the Artificial Analysis Intelligence Index: up to 1 of 4,
  none; at 2, the bottom of the mid band (37.6 on the 2026-10-17 catalog);
  from 3, the bottom of the frontier band (49.6); in between, in proportion
  (2.5 → 43.6). `math`, `rare` and `tools` raise it to the mid band, `long`
  to the frontier band; `code` still narrows to code-capable profiles. Every
  eligible profile at or above the minimum is a candidate, whatever its
  tier, and the cheapest wins; when none reaches it, the strongest eligible
  profile answers and says so (it used to fall to the default). Under
  `tiered-v1` the rating picked one tier and the cheapest profile on it won,
  so GPT-5.6 Luna (small, 37.3) answered an easy request ahead of a cheaper
  GLM 5.3 Flash (mid, 41.8), and a stronger mid model such as Kimi K3 never
  answered while a cheaper mid one was eligible. Each profile now carries a
  `score` (the index at its reasoning setting, or the bottom of its band
  when placed by hand); `check` prints it, and `decide` and every response
  disclose `minimum_score` and the chosen profile's `score`.
- **The LLM decider rates in half points** (0, 0.5 … 4), so a request
  between two levels gets a minimum between them. An answer off that grid,
  or not a number, is outside the schema and lands on the default. Checked
  live with DeepSeek Flash: it uses the half points (2.5, 3.5), about 1 s

## [0.27.0] — 2026-10-17

You choose the decision model; it governs the models you already pay for.

### Added

- **`delegation-router`**, a local model router. A `router` block in the
  personal configuration names the decision model (`decider`, required) and
  the profiles it governs (`pool`, `default`, on any adapter). `check`
  resolves it without network; `decide --prompt-file` recommends one profile
  and never dispatches it (`--raw` shows the decider's own answer); `serve`
  is an OpenAI-compatible `/v1/chat/completions` on loopback only. A
  `"model": "auto"` request goes through a deterministic prefilter (rung,
  context, cost ceiling, JSON mode, native limits), the decider and the
  `tiered-v1` policy — the lowest rung the answer allows, `code` narrowing,
  `math`/`rare`/`tools` lifting to `mid`, the cheapest eligible profile in
  the rung, escalation never descent, a 0.55 confidence floor — then one
  forward with the chosen profile's own key, streaming passed through. A pool
  profile named directly skips the decider. `mode: shadow` decides and
  discloses but dispatches the default.
- **Five deciders**, all asking the same question — how much capability,
  which specialties — and reporting the same signals: `llm` (one of your
  HTTP profiles, `temperature 0`, the excerpt in a `DATA` block, 120 tokens
  of room; DeepSeek with thinking disabled, Qwen at `minimal`), `sage`
  (Levanto, `scale` + `tags`), `jev` (TypeSafe System One, `score` +
  `noul`s; arithmetic-looking numbers never below `mid`), `dipylon` (your
  own `/decide`, one `yesno`), `classifier` (a local `POST {"text"}`), and
  `none` as the rules-only baseline. Each is called with its own credential
  and prices its decision; `url`, `credential_env`, `model` and `price`
  override the defaults. Sage, Jev and `llm` through DeepSeek and Qwen were
  probed live before the release (see the compatibility page).
- **Native profiles in the pool** through `delegation-run`: the
  conversation becomes a prompt file, the dispatcher runs the profile on its
  first read-only role in an empty temporary workdir, and the answer file
  comes back as one chat completion with the dispatcher's receipt under
  `router.delegation_run`. Timeouts, identity checks, OAuth locks and
  sandboxes stay with the dispatcher; its exit codes are mapped. No tools,
  images or JSON mode on a native profile; a stream is one event. This is
  how Claude models join a pool.
- **The ladder comes from a third party.** `config/catalog.json` places
  every model it can from the Artificial Analysis Intelligence Index with
  one published rule, `index-bands-v1` (frontier within 8 points of the best
  model of the day, mid within 20, small below), and records the evidence
  beside each row; a profile's own `tier` wins, a profile with `effort` is
  placed at that setting's index, and every decision names its placement
  (`tier_source`). `catalog show` prints the source of every rung; `catalog
  refresh` makes one request to the API with the user's key (`AA_API_KEY`,
  or `config/artificial-analysis.env` under the data home, mode 600) and
  writes `catalog.local.json`, which takes precedence while it is at least
  as recent; `--shipped` refreshes the shipped file before a release. The
  shipped snapshot of 2026-10-15 placed 24 of 25 models from the API and
  corrected four hand placements (GPT-5.6 Sol and GPT-5.5 are `mid`, GLM 5.2
  and Mistral Large 3 `small`). Data attribution: Artificial Analysis.
- **`delegation-router eval`**: an offline measure of one decider on a
  golden set the user assembled (prompt, paraphrases, recorded outcomes per
  profile). Reports accuracy, cost, optimal-selection ratio, robustness,
  undecidable rate, latency, the rules-only baseline, a deferral curve and
  an advisory `gate.json`. It calls the decider, never a pool profile.
- **Disclosure and refusals.** `X-Router-*` headers and a `router` object
  with signals, reasons (including the candidates of the chosen rung with
  their estimated cost), blocked profiles, usage, cost and the
  provider-reported model (`mismatch` disclosed, not fatal). Refusals that
  never reach a provider: unknown model, browser `Origin` outside
  `allow_origins` (a listed origin gets CORS), cost ceiling from the
  configuration or `X-Router-Max-Cost-USD`, invalid body, missing credential,
  busy. Provider failures keep their meaning and lose their payload. The
  server prints one listening line and nothing else. Opt-in receipts (JSONL,
  mode 600, no prompt content) survive `uninstall.sh`.
- `delegation-route check` reports the router; `doctor.sh` has a "Model
  router" section that opens with the decider and names the catalog in
  effect; the installer links `delegation-router` and ships the catalog and
  the decider prompt. The router suite, `tests/router/`, runs 64 tests
  against fake providers and services; CI runs ruff beside shellcheck.

### Changed

- **One idea, up front.** The README opens with the decision model and how

- **One configuration schema.** `delegation-config init` writes

- `bin/lib` has one module per domain: configuration, credentials, catalog,
  router policy, pipeline, deciders, bridge, server, eval.
